# LabInvoiceSystem 3.0.0

Rust + Tauri 2 + React 全新独立实现，保留旧版录入、核对、PDF 预览、归档、搜索、批量操作、导出、统计和主题工作流。

- 新增办公/生活用品、实验用品分类；旧发票保留“未分类（历史数据）”。
- 多 ZIP 只读预览后确认接收、旧八字段 Excel 兼容、Manifest v1 精确回导、跨批次去重、人工冲突核对。
- 旧 JSON 和原件复制迁移，先备份；SQLite 事务、不可变原件、软删除恢复。
- OCR 仅在明确授权后按需上传，凭据使用系统安全存储。
- Windows x64 NSIS、macOS Intel 和 Apple Silicon DMG / 更新包。
- 官方 Tauri Updater：延迟/定期/手动检查、稍后、跳过、下载进度、更新前排空操作与备份，验证签名及签名中的版本。

## 安装与签名状态

公开更新验收发现：首次使用 `/S` 静默安装、尚未保存安装语言时，NSIS 被动更新会停在语言选择对话框。3.0.0 的签名与版本校验已通过，完整无人值守升级尚未通过；3.0.1 正在修复并增加真实安装回归检查。实际进度见[验收记录](https://github.com/MIGO-OvO/LabInvoiceSystem/blob/main/docs/acceptance.md)。

Windows 安装包有 Tauri Updater 数字签名，暂未配置 Windows Authenticode 证书，首次安装可能出现 SmartScreen 提示。Updater 签名不等同于操作系统的发行者认证。

**macOS 当前为未公证预览构建。缺少 Apple Developer 发行证书和公证凭据，不能将其视为完成正式分发。macOS 包不加入正式在线更新清单。** 请查看本 Release 的 `release-security.json` 获取三个架构的实际签名和公证状态。配置 Apple Secrets 后，发布工作流会执行签名、公证验证并将通过的平台加入更新清单。

## 数据与兼容

3.0 使用独立本地数据目录。通过设置选择旧 `archive_data` 文件夹，先备份、再复制导入为待核对草稿；原目录可继续用于 Legacy。旧配置只迁移非敏感字段，OCR 凭据需重新配置。建议先迁移一个月份并核对完整性，再分批迁移其余资料。

原版完整存档：[LabInvoiceSystem-legacy](https://github.com/MIGO-OvO/LabInvoiceSystem-legacy)。使用说明与验收记录见仓库 `docs/`。
