# 3.0 使用说明

## 个人整理

1. 在“发票录入”选择文件，或拖入 PDF、JPG、PNG / ZIP。原件复制到本机工作区；导入结果先作为草稿。
2. 选择办公/生活用品或实验用品，核对原件与购买日期、录入日期、金额、项目、支付方式及发票身份。历史缺失字段保持空，不自动补历史日期或分类。
3. 可统一所选草稿的购买日期和支付方式、批量调整分类。逐张核对后勾选确认，或明确确认已核对全部原件后使用批量核对。
4. 归档必须通过字段校验和去重检查。相同原件不重复归档；身份冲突要保留已有、合并已核对字段或说明确为不同发票的理由。
5. 在“导出与归档”搜索、筛选并选中记录，导出 ZIP。ZIP 包含原件、兼容旧八字段的 Excel（增加分类与原件路径）和 Manifest v1。

金额采用两位小数。云 OCR 只是辅助识别，使用后仍需核对。

## 报账人员接收

一次选择或拖入多个 ZIP。每个来源独立检查，损坏包不影响其他成功来源；查看队列里的真实进度、错误/重复明细。取消不提交半个包，可重试。撤销批次会软删除该批次新增记录并撤销新增的重复来源关联。

新版 Manifest 优先精确映射并验证哈希；其校验和只能证明内容完整性。旧 Excel 无法唯一匹配时，在队列中选择该包的对应原件并点击匹配，不能根据相似字段猜对应。同名 ZIP 按包哈希区分；同一旧 ZIP 的同名原件按条目索引保留。

核对并归档后按分类、录入日期、购买日期和支付方式管理，查看仪表盘，统一导出。

## 历史迁移与回滚

设置 → 旧版迁移 → 选择 `archive_data` 或某个月份目录 → 查看文件数量与预览 → 备份并复制导入。旧 JSON 使用原有八字段，原件和 JSON 先备份，新记录作为待核对草稿。旧目录不修改。

先迁移一个月，确认数量、日期、金额和原件校验，再分批迁移。无分类的历史数据为“未分类（历史数据）”；缺录入日期时请人工补充。每批最多2048张、512 MiB，详见 ZIP 限制。

若需要回滚，可撤销此批次，然后继续使用 Legacy 和原目录。旧配置迁移保留主题、导出目录、额度与项目修正记忆；OCR 同意重新确认，敏感密钥需要重新输入安全存储。

## OCR 与隐私

在设置中保存百度 API Key 和 Secret Key 至系统凭据存储。测试连接仅请求鉴权；点击当前发票的云 OCR 前明确同意上传。程序没有自动批量上传。拒绝或未同意时可完整手工整理。

移除凭据会删除该应用的系统凭据项。导出不包含凭据。用量是本软件成功请求计数和本地自设额度，以百度控制台计费为准。

## 归档、恢复与备份

“移至已删除”保留原件与记录；“已删除”页可恢复。恢复会再次检查与已归档记录的重复，避免重复报账。编辑保留原件哈希及来源，关键变更前创建数据库快照。

设置可打开数据、备份和导出目录、执行归档完整性校验并查看操作日志。自行恢复数据库时先退出软件，完整备份当前数据目录，再用已验证快照恢复 `invoices.sqlite3`，并保留 `objects`；不要在运行时替换数据库或单独复制 WAL 文件。

## 更新

启动后4.5秒检查，每12小时检查，也可在设置手动检查。可立即更新、24小时后提醒或跳过指定版本；手动检查仍能找到跳过的版本。

安装前等待/取消当前导入与导出，保存草稿、checkpoint 和快照，再下载并验证数字签名及签名中的版本，完成后重启。失败会释放操作锁，可以继续使用已保存的草稿和归档。

当前 macOS 正式签名和公证未完成，因此不提供 macOS 正式在线更新。Windows Updater 签名与操作系统 Authenticode 认证是不同机制。
